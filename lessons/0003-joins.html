Lesson 0003 · DataFrame API

Joins

Glue two frames on a key. Most pipeline “enrich fact with dimension” work is this file’s syntax.

Win: Cold-write left.join(right, on, how) for inner/left/right/full/semi/anti, then project clean columns without ambiguous key errors.

0. Map: knowledge → exercise

ex1  join(..., "cust_id", "inner") + select
ex2  how="left"
ex3  how="right"
ex4  how="full" (or "outer")
ex5  how="left_semi"   — filter left by existence
ex6  how="left_anti"   — left rows with no match
ex7  join then filter
ex8  on = Column equality + alias + select

1. Toy data (same as drills)

orders
  order_id | cust_id | amount
         1 |      10 |    100
         2 |      20 |    200
         3 |      10 |     50
         4 |      99 |     80   ← no customer

customers
  cust_id | name  | region
       10 | Alice | east
       20 | Bob   | west
       30 | Carol | east      ← no orders

2. Signature

left.join(right, on=None, how=None)

  • on — key string, list of key strings, or a boolean Column (or list of Columns).
  • how — default "inner". Also left/left_outer, right/right_outer, full/outer, left_semi, left_anti, cross, …
orders.join(customers, "cust_id", "inner")
orders.join(customers, ["cust_id"], "left")
orders.join(customers, orders.cust_id == customers.cust_id, "inner")

3. String key vs Column condition (critical)

A. Shared name as string — equi-join, one key column

orders.join(customers, "cust_id", "inner")
# output has ONE cust_id, plus other cols from both sides

Use this when both frames share the same key column name. Drills ex1–ex7 use this style.

B. Column equality — both key columns kept

orders.join(customers, orders.cust_id == customers.cust_id, "inner")
# two cust_id columns → ambiguous if you select("cust_id")

Fix with aliases and qualified selects (ex8): 

o = orders.alias("o")
c = customers.alias("c")
(
    o.join(c, col("o.cust_id") == col("c.cust_id"), "inner")
     .select(
         col("o.order_id").alias("order_id"),
         col("c.name").alias("name"),
         col("o.amount").alias("amount"),
     )
)

4. Join types (what rows survive)

how Keeps Drill
inner matches only ex1
left all left; right null if miss ex2
right all right; left null if miss ex3
full / outer both sides; nulls either way ex4
left_semi left rows that match; left cols only ex5
left_anti left rows with no match; left cols only ex6

Inner (ex1)

orders.join(customers, "cust_id", "inner").select(
    "order_id", "name", "amount"
)
# → (1, Alice, 100), (2, Bob, 200), (3, Alice, 50)
# order 4 dropped; Carol never appears

Left (ex2)

orders.join(customers, "cust_id", "left").select(
    "order_id", "name", "amount"
)
# order 4 kept with name = null

"left", "left_outer", "leftouter" are the same family (official aliases).

Right (ex3)

orders.join(customers, "cust_id", "right").select("name", "order_id")
# Carol kept with order_id = null
# Alice appears twice (two orders)

Full outer (ex4)

orders.join(customers, "cust_id", "full").select("order_id", "name")
# orphan order 4 AND orphan Carol both present

Semi / anti (ex5, ex6)

Existence filters — result columns come from the left frame only.

# orders that have a customer (ex5)
orders.join(customers, "cust_id", "left_semi").select(
    "order_id", "cust_id", "amount"
)

# orders with no customer (ex6)
orders.join(customers, "cust_id", "left_anti").select(
    "order_id", "cust_id", "amount"
)
# note: after key join, column order may put cust_id first —
# always select() when the checker (or your contract) cares about order

5. Join then filter (ex7)

(
    orders.join(customers, "cust_id", "inner")
          .filter(col("region") == "east")
          .select("order_id", "name", "region", "amount")
)
# Alice's two orders only (Bob west dropped)

Filter after join uses columns from either side (once joined, one flat schema for string-key joins).

7. Work mental model

  • Fact left, dimension right, left join → keep all facts.
  • Need “exists in other table?” without bringing columns → left_semi.
  • Need “missing dimension?” → left_anti.
  • Duplicate key column names after Column-join → alias + qualified select.
