Window functions

Keep every row, add ranks / lags / running totals over a partition. Work pipelines need this after groupBy fluency.

Win: Cold-write fn().over(Window.partitionBy(...).orderBy(...)) for row_number, rank, lag, and window sum.

2. Mental model

groupBy + agg collapses rows (one row per key). Window keeps all rows and adds columns computed over a peer set. 

from pyspark.sql import Window
from pyspark.sql.functions import col, row_number, rank, dense_rank, lag, lead, sum

w = Window.partitionBy("region").orderBy(col("amount").desc())
df.withColumn("rn", row_number().over(w))

Spec pieces (official Window):

  • partitionBy — peers (like group key; optional)
  • orderBy — order inside partition (required for rank/lag/running)
  • rowsBetween / rangeBetween — frame; defaults matter

Default frame (docs): no order → whole partition; with order → growing frame from unbounded preceding to current row (running aggregates “just work”).

3. Core patterns (solution kit)

ex1 — row_number (unique ranks)

w = Window.partitionBy("region").orderBy(col("amount").desc(), col("id"))
orders.withColumn("rn", row_number().over(w)).select("id", "region", "amount", "rn")
# east: id2 rn=1, id3 rn=2, id1 rn=3, id7 rn=4
# west: id6 rn=1, id4 rn=2, id5 rn=3
# Secondary orderBy id makes ties deterministic.

ex2 — rank (Olympic gaps)

w = Window.partitionBy("region").orderBy(col("amount").desc())
orders.withColumn("r", rank().over(w)).select("id", "region", "amount", "r")
# east amounts 200,200,100,50 → ranks 1,1,3,4 (gap after tie)
# west 300,150,80 → 1,2,3

ex3 — dense_rank (no gaps)

w = Window.partitionBy("region").orderBy(col("amount").desc())
orders.withColumn("d", dense_rank().over(w)).select("id", "region", "amount", "d")
# east 200,200,100,50 → 1,1,2,3

ex4 — lag previous amount

w = Window.partitionBy("region").orderBy("day")
orders.withColumn("prev", lag("amount").over(w)).select("id", "region", "day", "amount", "prev")
# first day in region → null

ex5 — lead next amount

w = Window.partitionBy("region").orderBy("day")
orders.withColumn("nxt", lead("amount").over(w)).select("id", "region", "day", "amount", "nxt")
# last day in region → null

ex6 — total over whole partition

w = Window.partitionBy("region")   # no orderBy → full partition frame
orders.withColumn("reg_total", sum("amount").over(w)).select("id", "region", "amount", "reg_total")
# east every row 550; west every row 530
# Rows kept (unlike groupBy).

ex7 — running total by day

w = Window.partitionBy("region").orderBy("day")
orders.withColumn("running", sum("amount").over(w)).select("id", "region", "day", "amount", "running")
# east: 100 → 300 → 500 → 550

ex8 — top amount row per region

w = Window.partitionBy("region").orderBy(col("amount").desc(), col("id"))
(
    orders.withColumn("rn", row_number().over(w))
          .filter(col("rn") == 1)
          .select("id", "region", "amount")
)
# east id2 amount 200; west id6 amount 300

5. Work mental model

  • Need one row per group → groupBy. Need annotate every row → window.
  • Top-N per key: row_number then filter(rn <= N).
  • Day-over-day: lag then subtract (null first day).
  • Always decide partitionBy + orderBy before picking the function.
