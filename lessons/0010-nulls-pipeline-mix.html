Nulls + pipeline mix

0. Why this exists

You passed isolated nulls (0009). Fluency = compose them with join/filter/agg without reopening docs. Same pattern as 0004 / 0006 / 0008.

1. Toolbox (all you need)

from pyspark.sql.functions import col, coalesce, lit, sum, when

# null detect / bulk
col("amount").isNull()
col("amount").isNotNull()
df.na.drop(subset=["amount", "status"])
df.na.fill({"amount": 0})

# null fill mid-chain
df.withColumn("region", coalesce(col("region"), lit("unknown")))
when(col("amount").isNull(), "missing").otherwise("ok")

# compose
df.filter(col("status").isNull() | (col("status") == "open"))
df.join(right, "key", "inner")   # or "left"
df.groupBy("name").agg(sum("amount").alias("total"))

3. Knowledge → each exercise

ex1 — null amounts only

orders.filter(col("amount").isNull())
# order_id 2, 7

ex2 — fill amount → 0, then open

(
    orders.na.fill({"amount": 0})
          .filter(col("status") == "open")
)
# id2 amount becomes 0 and stays (open)

ex3 — drop null amount/status → inner join

(
    orders.na.drop(subset=["amount", "status"])
          .join(customers, "cust_id", "inner")
)
# drops 2,3,7 (nulls) and 4 (orphan)

ex4 — left join → coalesce region

(
    orders.join(customers, "cust_id", "left")
          .withColumn("region", coalesce(col("region"), lit("unknown")))
)
# Bob + orphan region → "unknown"; orphan name stays null

ex5 — open OR null status, amount present

orders.filter(
    (col("status").isNull() | (col("status") == "open"))
    & col("amount").isNotNull()
)
# keeps 1,3,4,6 — drops open+null amount (id2)

ex6 — fill → inner join → sum by name

(
    orders.na.fill({"amount": 0})
          .join(customers, "cust_id", "inner")
          .groupBy("name")
          .agg(sum("amount").alias("total"))
)
# Alice 340, Bob 150, Carol 300

ex7 — inner join → missing-amount flag

(
    orders.join(customers, "cust_id", "inner")
          .select(
              "order_id", "name",
              when(col("amount").isNull(), "missing")
                .otherwise("ok").alias("flag"),
          )
)
# id2 Bob missing; id7 Carol missing

ex8 — fill → open → join → coalesce region → sum

(
    orders.na.fill({"amount": 0})
          .filter(col("status") == "open")
          .join(customers, "cust_id", "inner")
          .withColumn("region", coalesce(col("region"), lit("unknown")))
          .groupBy("region")
          .agg(sum("amount").alias("total"))
)
# east 400 (Alice 100 + Carol 300); unknown 0 (Bob filled open)

4. Order habits (work)

  • Fill or drop before sum/avg when nulls would undercount or vanish in agg.
  • status == "open" alone drops null status — OR with isNull if unknown status should stay.
  • Left join keeps orphans; coalesce on right-side cols after join is the usual defaulting pattern.
  • Inner join after drop: orphans and null-key mess both disappear — know which you meant.
