2. Mental model

Transforms are lazy. Write is an action — it runs the plan and lands files. Read builds a new DataFrame from those files (or from object storage at work). 

# write
df.write.mode("overwrite").parquet(path)
df.write.mode("overwrite").option("header", True).csv(path)
df.write.mode("overwrite").partitionBy("region").parquet(path)

# read
spark.read.parquet(path)
spark.read.option("header", True).option("inferSchema", True).csv(path)

# same idea, format/save style
df.write.format("parquet").mode("overwrite").save(path)
spark.read.format("parquet").load(path)

Modes (when path/table already exists): overwrite replace · append add rows · ignore no-op · error / errorifexists throw. Docs: Writer.mode · DataFrameWriter · DataFrameReader · Parquet guide · CSV guide

3. Core patterns (solution kit)

ex1 — parquet roundtrip

orders.write.mode("overwrite").parquet(path)
spark.read.parquet(path)

ex2 — CSV with header

orders.write.mode("overwrite").option("header", True).csv(path)
(
    spark.read
         .option("header", True)
         .option("inferSchema", True)
         .csv(path)
)
# without inferSchema, numbers often come back as strings

ex3 — filter then write

(
    orders.filter(col("status") == "open")
          .write.mode("overwrite")
          .parquet(path)
)
spark.read.parquet(path)
# ids 1, 2, 4

ex4 — partitionBy region

orders.write.mode("overwrite").partitionBy("region").parquet(path)
(
    spark.read.parquet(path)
         .filter(col("region") == "east")
         .select("order_id", "region", "amount", "status")
)
# layout on disk: path/region=east/…  path/region=west/…
# select: partition cols may land at end of schema — pin order

ex5 — append doubles rows

orders.write.mode("overwrite").parquet(path)
orders.write.mode("append").parquet(path)
spark.read.parquet(path)
# 4 rows × 2 = 8

4. Traps (work)

  • Path is a directory of part files — not one .csv blob (unless you force single partition).
  • CSV without header/inferSchema (or an explicit schema) is painful at work.
  • append stacks files; duplicates are your problem. Prefer overwrite + full rebuild when unsure.
  • partitionBy is directory layout for pruning — not the same as window partitionBy.
  • Default write mode is error if path exists — habit: always set mode deliberately.
