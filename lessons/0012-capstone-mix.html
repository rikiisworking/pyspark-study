0. Why this exists

Core APIs through read/write are done. Storage strength = interleave them without docs. Same pattern as 0004 / 0006 / 0010 — now with files in the middle.

1. Toolbox (all you need)

from pyspark.sql import Window
from pyspark.sql.functions import col, coalesce, lit, row_number, sum

# chain
df.na.fill({"amount": 0}).filter(...).join(right, "key", "inner")
df.groupBy("name").agg(sum("amount").alias("total"))
df.withColumn("region", coalesce(col("region"), lit("unknown")))

# window
w = Window.partitionBy("name").orderBy(col("amount").desc(), col("order_id"))
df.withColumn("rn", row_number().over(w)).filter(col("rn") == 1)

# I/O
df.write.mode("overwrite").parquet(path)
df.write.mode("overwrite").partitionBy("region").parquet(path)
df.write.mode("overwrite").option("header", True).csv(path)
spark.read.parquet(path)
spark.read.option("header", True).option("inferSchema", True).csv(path)

3. Knowledge → each exercise

ex1 — fill → join → sum by name

(
    orders.na.fill({"amount": 0})
          .join(customers, "cust_id", "inner")
          .groupBy("name")
          .agg(sum("amount").alias("total"))
)
# Alice 340, Bob 150, Carol 300

ex2 — drop null amount/status → inner join

(
    orders.na.drop(subset=["amount", "status"])
          .join(customers, "cust_id", "inner")
)
# drops 2,3,7 and orphan 4

ex3 — open → parquet → read

orders.filter(col("status") == "open").write.mode("overwrite").parquet(path)
spark.read.parquet(path)

ex4 — fill → join → partitionBy region → read east

(
    orders.na.fill({"amount": 0})
          .join(customers, "cust_id", "inner")
          .write.mode("overwrite")
          .partitionBy("region")   # disk folders, not filter-first
          .parquet(path)
)
(
    spark.read.parquet(path)
         .filter(col("region") == "east")
         .select("order_id", "name", "region", "amount")
)
# Bob lands under null partition; east = Alice+Carol rows (amount 0 filled on id7)

ex5 — overwrite open, then overwrite closed

# second overwrite replaces path → only closed rows
# ids 5, 7, 8

ex6 — CSV full write, filter open after read

orders.write.mode("overwrite").option("header", True).csv(path)
(
    spark.read.option("header", True).option("inferSchema", True).csv(path)
         .filter(col("status") == "open")
)
# Do NOT filter before write — ticket is “load then filter”

ex7 — top open amount per name (window)

w = Window.partitionBy("name").orderBy(col("amount").desc(), col("order_id"))
(
    orders.filter((col("status") == "open") & col("amount").isNotNull())
          .join(customers, "cust_id", "inner")
          .withColumn("rn", row_number().over(w))
          .filter(col("rn") == 1)
          .select("order_id", "name", "amount")
)
# Alice 100, Carol 300 — Bob open has null amount, dropped

ex8 — open fill sum by region

(
    orders.na.fill({"amount": 0})
          .filter(col("status") == "open")
          .join(customers, "cust_id", "inner")
          .withColumn("region", coalesce(col("region"), lit("unknown")))
          .groupBy("region")
          .agg(sum("amount").alias("total"))
)
# east 400, unknown 0 (Bob)

4. Order habits (work)

  • Fill/drop before agg when nulls would undercount.
  • Write partitionBy = folder layout; filter partition after read (or path prune).
  • CSV: write full often; filter is a read-side choice.
  • Top-N: row_number + filter — not groupBy max + rejoin unless needed.
