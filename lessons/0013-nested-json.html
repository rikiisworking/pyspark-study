Lesson 0013 · DataFrame API

Nested columns + JSON strings

Work data is rarely flat. Pull fields from structs and JSON text, then explode arrays.

Win: Cold-write col("a.b"), from_json + DDL schema, get_json_object, explode / explode_outer.

2. Mental model

Two shapes at work:

  • Typed nested — parquet/ORC already has STRUCT / ARRAY. Use dot paths: col("user.id").
  • JSON string column — still text until you parse. Prefer from_json + schema when you need real types and nested fields. Use get_json_object for one quick path (returns string).
from pyspark.sql.functions import col, from_json, get_json_object, explode, explode_outer

# already a struct
col("user.id")
col("user.name")

# JSON string → typed struct
schema = "user STRUCT<id:INT, name:STRING>, amount INT, tags ARRAY<STRING>"
df.withColumn("p", from_json(col("raw"), schema))
col("p.user.id")
col("p.amount")
col("p.tags")

# one path, no schema (string out)
get_json_object(col("raw"), "$.user.id")

# array → rows
explode(col("p.tags"))        # empty array drops the parent row
explode_outer(col("p.tags"))  # empty array → one row, element null

3. Core patterns (solution kit)

ex1 — struct field select

orders.select(
    "order_id",
    col("user.name").alias("name"),
    "amount",
)

ex2 — filter nested

(
    orders.filter(col("user.id") == 10)
          .select("order_id", col("user.name").alias("name"), "amount")
)
# order_id 1, 3

ex3 — from_json then project

schema = "user STRUCT<id:INT, name:STRING>, amount INT, tags ARRAY<STRING>"
(
    events.withColumn("p", from_json(col("raw"), schema))
          .select(
              "event_id",
              col("p.user.id").alias("user_id"),
              col("p.amount").alias("amount"),
          )
)

ex4 — get_json_object (no full schema)

events.select(
    "event_id",
    get_json_object(col("raw"), "$.user.id").cast("int").alias("user_id"),
)
# path is JSONPath; result is string until you cast

ex5 / ex6 — explode vs explode_outer

# after from_json → p.tags
.select("event_id", explode(col("p.tags")).alias("tag"))
# event 3 (empty tags) disappears

.select("event_id", explode_outer(col("p.tags")).alias("tag"))
# event 3 stays, tag = null

ex7 — parse + filter

# from_json, filter p.amount >= 100, select event_id / user_id / amount
# rows: (1, 10, 100), (3, 10, 200)

ex8 — parse + groupBy

(
    events.withColumn("p", from_json(col("raw"), schema))
          .groupBy(col("p.user.id").alias("user_id"))
          .agg(sum("p.amount").alias("total"))
)
# 10→300, 20→50, 30→80

4. Traps (work)

  • from_json needs a schema (DDL string or StructType). Bad JSON → null struct, not throw.
  • get_json_object returns string. Cast when you need int/compare.
  • Dot path col("user.id") only works if user is already a struct — not if it is still a JSON string.
  • explode drops empty/null arrays; explode_outer keeps the parent row.
  • After explode, row count grows — joins/aggs after flatten change grain.
