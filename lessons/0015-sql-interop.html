2. Mental model

DataFrame API and Spark SQL share the same Catalyst plan. Interop is not a second engine — it is a bridge for notebooks, ad-hoc SQL, and colleague queries.

  • Local temp view — session-scoped. Prefer createOrReplaceTempView. Query as orders.
  • Global temp view — application-scoped, lives under system DB global_temp. Query as global_temp.view_name.
  • spark.sql always returns a DataFrame. You can .filter / withColumn after.
  • selectExpr — SQL fragments on one DF, no view registration.
# local temp view (session lifetime)
orders.createOrReplaceTempView("orders")
spark.sql("SELECT * FROM orders WHERE status = 'open'")

# global temp view (app lifetime; qualified name)
orders.createOrReplaceGlobalTempView("orders_g")
spark.sql("SELECT * FROM global_temp.orders_g")

# SQL fragments without a view
orders.selectExpr("order_id", "amount * 2 AS double_amt")

# drop when done (optional in short scripts)
spark.catalog.dropTempView("orders")
spark.catalog.dropGlobalTempView("orders_g")

3. When SQL vs DataFrame

Mission default: DataFrame API for pipelines you own (typed columns, composable functions, fewer string bugs). SQL is fine when:

  • Exploring in a notebook / one-off ticket
  • Colleague already wrote solid SQL
  • A multi-join CTE reads clearer as SQL than a long DF chain

Either path compiles to the same planner — pick readability for the reader (you, or your teammate).

4. Core patterns (solution kit)

ex1 — register + filter

orders.createOrReplaceTempView("orders")
spark.sql("""
  SELECT order_id, amount, status
  FROM orders
  WHERE status = 'open'
""")
# ids 1, 2, 4

ex2 — two views + join

orders.createOrReplaceTempView("orders")
customers.createOrReplaceTempView("customers")
spark.sql("""
  SELECT o.order_id, c.name, o.amount
  FROM orders o
  INNER JOIN customers c ON o.cust_id = c.cust_id
""")

ex3 — SQL agg

orders.createOrReplaceTempView("orders")
spark.sql("""
  SELECT status, SUM(amount) AS total
  FROM orders
  GROUP BY status
""")
# open → 300, closed → 200

ex4 — selectExpr (no view)

orders.selectExpr("order_id", "amount * 2 AS double_amt")

ex5 — SQL then DF chain

orders.createOrReplaceTempView("orders")
(
    spark.sql("SELECT order_id, amount FROM orders WHERE status = 'open'")
         .withColumn("tax", col("amount") * 0.1)
         .select("order_id", "amount", "tax")
)

ex6 — replace view

# first bind open-only under name "v"
orders.filter(col("status") == "open").createOrReplaceTempView("v")
# replace with full frame
orders.createOrReplaceTempView("v")
spark.sql("SELECT order_id, status FROM v")
# all 4 rows — replace wins

ex7 — global_temp

orders.createOrReplaceGlobalTempView("orders_g")
spark.sql("""
  SELECT order_id, amount
  FROM global_temp.orders_g
  WHERE amount >= 100
""")
# bare FROM orders_g fails — must qualify

ex8 — join + filter in SQL

orders.createOrReplaceTempView("orders")
customers.createOrReplaceTempView("customers")
spark.sql("""
  SELECT o.order_id, c.name, o.amount, c.region
  FROM orders o
  INNER JOIN customers c ON o.cust_id = c.cust_id
  WHERE o.status = 'open' AND c.region = 'east'
""")
# (1 Alice 100 east), (4 Carol 150 east)

5. Traps (work)

  • createTempView throws if the name exists — prefer createOrReplaceTempView.
  • Local view dies with the session; global dies with the application.
  • Global must be global_temp.view_name — bare name is a different catalog path.
  • View name is not the Python variable. df.createOrReplaceTempView("orders") then FROM orders.
  • SQL strings use single quotes for literals: status = 'open'.
  • spark.sql returns a DF — column names follow your SQL aliases.
