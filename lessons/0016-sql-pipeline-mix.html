0. Why this exists

You passed isolated SQL interop (0015). Storage strength = interleave views with filter, join, fill, groupBy, window, parquet. Same pattern as 0010 / 0014. Also closes the selectExpr gap from 0015 (ex4 used withColumn instead).

1. Toolbox (all you need)

from pyspark.sql import Window
from pyspark.sql.functions import col, coalesce, lit, sum, row_number

# bridge
df.createOrReplaceTempView("orders")
spark.sql("SELECT … FROM orders …")          # → DataFrame
df.selectExpr("order_id", "amount * 2 AS double_amt")

# you already know these after SQL
.filter(col("region") == "east")
.withColumn("region", coalesce(col("region"), lit("unknown")))
.na.fill({"amount": 0})
.groupBy("region").agg(sum("amount").alias("total"))
Window.partitionBy("name").orderBy(col("amount").desc(), col("order_id"))
.write.mode("overwrite").parquet(path)
spark.read.parquet(path)

3. Knowledge → each exercise

ex1 — SQL open → selectExpr double

orders.createOrReplaceTempView("orders")
(
  spark.sql("SELECT order_id, amount FROM orders WHERE status = 'open'")
       .selectExpr("order_id", "amount", "amount * 2 AS double_amt")
)
# null amount → null double_amt (row 6)

ex2 — SQL join → DF filter east

# register both, INNER JOIN all, then .filter(col("region") == "east")
# (1 Alice 100 east), (3 Alice 200 east), (4 Carol 150 east)

ex3 — SQL sum → DF having-style filter

# SUM(amount) by status (SQL skips nulls in SUM)
# open = 100+50+150+80 = 380; closed = 200
# then .filter(col("total") > 250) → open only

ex4 — DF open first → SQL join

orders.filter(col("status") == "open").createOrReplaceTempView("open_orders")
customers.createOrReplaceTempView("customers")
# INNER JOIN → drops orphan 5; keeps Bob null amount
# (1 Alice 100), (2 Bob 50), (4 Carol 150), (6 Bob null)

ex5 — SQL left join → coalesce region

# open LEFT JOIN customers, then coalesce(region, "unknown")
# orphan 5 → name null, region unknown
# Bob null region → unknown

ex6 — SQL join → window top per name

# SQL: open AND amount IS NOT NULL, inner join
# Window.partitionBy("name").orderBy(amount desc, order_id)
# rn == 1 → Alice 1/100, Bob 2/50, Carol 4/150

ex7 — SQL open join → fill → sum by region

# fill amount 0 so Bob null becomes 0; coalesce region unknown
# east: 100+150 = 250; unknown: 50+0 = 50
# orphan dropped by INNER

ex8 — SQL open → parquet roundtrip

# SELECT order_id, cust_id, amount WHERE open
# write.mode("overwrite").parquet(path); spark.read.parquet(path)
# includes orphan 5 and null amount on 6

4. Traps (work)

  • Either direction: DF → register → SQL, or SQL → DF chain. Both return DataFrames.
  • selectExpr is the no-view bridge — prefer it over withColumn when the drill says so.
  • SQL SUM skips nulls; DF fill-before-sum if null must count as 0 (ex7).
  • View name ≠ Python variable. Filter DF first, then createOrReplaceTempView("open_orders").
  • Left join keeps orphans; inner drops them. Coalesce after left if region may be null.
  • Top-N: drop null amounts in SQL (IS NOT NULL) before window if null must not win.
