2. Spark 4 parse rule

to_date converts with an optional pattern from the datetime pattern doc (yyyy-MM-dd, dd/MM/yyyy, HH:mm:ss). On this Spark 4.2 session a mismatch throws DateTimeException: [CANNOT_PARSE_TIMESTAMP] and tells you to use try_to_date (new in 4.0) — “NULL instead of raising.” 

from pyspark.sql.functions import (
    col, lit, coalesce, try_to_date, to_timestamp, try_to_timestamp,
    date_trunc, datediff, date_format, year, month, sum,
)

# dirty work column — do not use to_date
try_to_date(col("sold_at"), "yyyy-MM-dd")          # row 4 → null
try_to_date(col("sold_at"), "dd/MM/yyyy")          # row 4 → 2026-01-15

# two formats on one column
coalesce(
    try_to_date(col("sold_at"), "yyyy-MM-dd"),
    try_to_date(col("sold_at"), "dd/MM/yyyy"),
)

# timestamp: to_timestamp accepts a format string
to_timestamp(col("ts"), "yyyy-MM-dd HH:mm:ss")

# try_to_timestamp format is a Column — wrap lit (Spark 4)
try_to_timestamp(col("ts"), lit("yyyy-MM-dd HH:mm:ss"))

3. After you have a date

d  = try_to_date(col("sold_at"), "yyyy-MM-dd")
sh = try_to_date(col("shipped_at"), "yyyy-MM-dd")

# date_trunc → timestamp at 00:00:00; format if you want a date-looking string
# formats: year / month / day / week / quarter / hour / …
date_format(date_trunc("month", d), "yyyy-MM-dd")   # 2026-01-01

datediff(sh, d)    # days from start to end — datediff(end, start)
# row1: 5; row2: 2; row3: 0; null if either side null

year(d)            # 2026
month(d)           # 1 or 2
date_format(d, "dd-MM-yyyy")   # "15-01-2026"

5. Traps (work)

  • Spark 4 + dirty strings: try_to_date, not to_date.
  • try_to_timestamp(col, lit("pattern")) — a bare format string is read as a column name.
  • datediff(end, start) — backwards gives a negative (docs: “days from start to end”).
  • date_trunc returns a timestamp (midnight). date_format if the checker wants yyyy-MM-dd.
  • A timestamp string does not parse as yyyy-MM-dd — include HH:mm:ss or use to_timestamp.
