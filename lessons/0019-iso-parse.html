Lesson 0019 · vocabulary (not a new function)

What “ISO parse” means

It is shorthand in these drills, not a Spark API. Read a YYYY-MM-DD string into a date.

Win: When an exercise says “ISO-parse sold_at”, type try_to_date("sold_at", "yyyy-MM-dd") without looking it up.

1. ISO is a date shape

ISO 8601 is the international date/time writing rule. ISO’s own summary: represent a calendar day as YYYY-MM-DD — year, then month, then day. Example: 27 September 2022 is 2022-09-27.

Why it exists: 01/05/22 is January 5 or May 1 depending on country (same ISO page). Year-first with hyphens is unambiguous and sorts as text (RFC 3339 §5.1 — an Internet profile of ISO 8601 — notes that year-month-day strings order correctly). 

2026-01-15     ISO date     (year-month-day)
15/01/2026     EU day-first (not ISO)
01/15/2026     US month-first (not ISO)
2026-01-15 14:30:00   date + clock (ISO-like; needs a timestamp pattern)

2. Parse is the verb

The column is still a string until you convert it. Parse = apply a pattern and get a Spark DateType (or null / error). Pattern letters come from Spark’s datetime pattern doc — yyyy year, MM month, dd day. Hyphens in the pattern must match hyphens in the string. 

# "ISO parse" in 17_datetime.py  ≡
try_to_date(col("sold_at"), "yyyy-MM-dd")

# "EU parse" in this course      ≡
try_to_date(col("sold_at"), "dd/MM/yyyy")

There is no function named iso_parse. The docstring is naming the pattern, same as “ISO-parse shipped_at and sold_at” in ex5.

3. Your toy rows

sold_at        ISO parse (yyyy-MM-dd)
2026-01-15     2026-01-15     ✓
2026-01-31     2026-01-31     ✓
2026-02-01     2026-02-01     ✓
15/01/2026     null           (needs EU pattern)
null           null

Row 4 is a real 15 Jan 2026, but not written as ISO — so an ISO parse correctly returns null. That is why ex2 coalesces ISO then EU.
