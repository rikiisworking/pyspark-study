0. Why this exists

You passed isolated datetime (0018). Storage strength = interleave parse with filter, join, fill, groupBy, window, parquet. Same pattern as 0014 / 0016. Also closes the 0018 gap: clock lives in ts, not sold_at.

1. Toolbox (all you need)

from pyspark.sql import Window
from pyspark.sql.functions import (
    col, coalesce, lit, sum, row_number,
    try_to_date, try_to_timestamp,
    date_trunc, datediff, date_format,
)

# parse early — dirty work column, then treat as a date
.withColumn("sold", try_to_date(col("sold_at"), "yyyy-MM-dd"))   # ISO parse
coalesce(try_to_date("sold_at", "yyyy-MM-dd"),
         try_to_date("sold_at", "dd/MM/yyyy"))                   # ISO then EU

# clock: ts, not sold_at. try_to_timestamp format is a Column
try_to_timestamp(col("ts"), lit("yyyy-MM-dd HH:mm:ss"))

# you already know these after 0018
.filter((col("status") == "open") & (col("sold") > "2026-01-10"))
.join(customers, "cust_id")                       # inner
.na.fill({"amount": 0})
date_format(date_trunc("month", col("sold")), "yyyy-MM-dd")
datediff(col("shipped"), col("sold"))             # end, start
Window.partitionBy("month_start").orderBy(col("amount").desc(), col("order_id"))
.write.mode("overwrite").parquet(path)
spark.read.parquet(path)

4. Traps (work)

  • Parse early. Filter/join/trunc on the date column, not the raw string.
  • ISO parse leaves EU 15/01/2026 null. Coalesce if both formats are legal.
  • Null sold fails > — the row drops. That is three-valued logic, not a crash.
  • Clock is ts. sold_at is a calendar day.
  • try_to_timestamp(..., lit("pattern")) — bare string is a column name.
  • datediff(end, start). Fill amount before sum if null must count as 0 (ex7).
