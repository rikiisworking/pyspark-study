Union + pipeline mix

0. Why this exists

You passed isolated union (0021). Storage strength = interleave unionByName with filter, join, fill, groupBy, window, parquet. Same pattern as 0016 / 0020. Window fixture: min order_id is not max amount (the 0020 ex6 miss).

1. Toolbox (all you need)

from pyspark.sql import Window
from pyspark.sql.functions import col, coalesce, lit, sum, row_number

# stack — west_shuf seats are swapped; do not union
east.unionByName(west_shuf)
east.unionByName(west_extra, allowMissingColumns=True)

# tag *before* the stack
east.withColumn("src", lit("east")).unionByName(
    west_shuf.withColumn("src", lit("west"))
)

# then the pipeline you already know
.filter(col("status") == "open")
.join(customers, "cust_id")                    # inner
.join(dim, "cust_id", "left")
.na.fill({"amount": 0})
.distinct()
Window.partitionBy("name").orderBy(col("amount").desc(), col("order_id"))
.write.mode("overwrite").parquet(path)

4. Traps (work)

  • west_shuf is shuffled. union silently swaps amount into order_id.
  • Tag src before the stack or you cannot filter one extract.
  • Two region columns after join — rename the dim side first.
  • Fill amount before sum. Nulls are skipped.
  • Top-N: orderBy(col("amount").desc(), col("order_id")). This toy set punishes orderBy("order_id").
